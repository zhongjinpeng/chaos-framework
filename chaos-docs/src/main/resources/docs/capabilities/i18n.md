# 错误文案国际化（chaos-core + chaos-web）

> 仓库中不存在 `chaos-i18n` 模块。文案解析契约位于 `chaos-web`（包 `com.michael.chaos.web.i18n`），
> 错误码上的消息 key 约定位于 `chaos-core` 的 `ErrorCode`。

## 解决的问题

框架返回给调用方的文案有三个来源：错误码默认消息、异常携带的自定义消息、框架内置的参数校验提示。
设计早期前两者是英文而第三类是硬编码中文，同一个服务的错误响应会中英混杂：

```json
{ "code": "500", "message": "internal server error" }
{ "code": "400", "message": "缺少必填请求头: X-Required" }
```

而且无论客户端声明什么语言，拿到的都是同一段文案。现在所有文案统一经过 `ErrorMessageResolver` 解析，
语言一致，且 `Accept-Language` 对框架内置提示同样生效。

## 组成

| 能力 | 位置 |
| --- | --- |
| `ErrorCode.messageKey()`（消息 key 约定） | chaos-core `core.exception` |
| `ErrorMessageResolver`（解析契约） | chaos-web `web.i18n` |
| `MessageSourceErrorMessageResolver`（默认实现） | chaos-web `web.i18n` |
| `ChaosMessageKeys`（内置提示 key 常量） | chaos-web `web.i18n` |
| 内置资源包 `chaos-web[_zh_CN|_zh].properties` | chaos-web `com/michael/chaos/web/i18n/messages/` |

## 查找顺序

1. 应用自己的 `MessageSource`（Spring Boot 默认即 `messages.properties`）——业务可以覆盖任何框架文案；
2. 框架内置资源包；
3. 调用方给出的兜底文案（错误码的 `message()`）。

框架资源包关闭了 `fallbackToSystemLocale`：未命中的语言确定性地回退到英文根资源包，不会随部署机器的 locale 漂移。

## 语言选择

```yaml
chaos:
  web:
    i18n:
      enabled: true         # 关闭后直接使用错误码默认消息，不做任何查找
      default-locale: ""    # 留空 = 按请求语言；填 zh-CN / en 则固定
```

留空时按 `LocaleContextHolder` 的当前语言解析，Spring MVC 默认从 `Accept-Language` 读取；
客户端未声明时取服务端默认语言。只提供单一语言的内部系统建议显式固定，避免响应语言随客户端变化。

## 消息 key 约定

| 错误码 | 消息 key |
| --- | --- |
| 框架内置 `CommonErrorCode` | `chaos.error.common.<枚举名转短横线>`，如 `chaos.error.common.bad-request` |
| 业务自定义 `ErrorCode` | `chaos.error.<code>`，如 `chaos.error.10001` |

两个命名空间刻意分开：业务枚举里出现 `404`、`500` 这类数字码相当常见，共用命名空间会让业务文案被框架文案顶掉。

业务错误码可以覆盖 `messageKey()` 使用自己的命名空间：

```java
public enum OrderErrorCode implements ErrorCode {
    ALREADY_CANCELLED("10001", "order already cancelled");

    @Override
    public String messageKey() {
        return "order.error." + code();
    }
}
```

## 覆盖框架文案

在应用的 `src/main/resources/messages.properties` 中定义同名 key：

```properties
chaos.error.common.too-many-requests=系统繁忙，请稍后再试
chaos.web.missing-parameter=参数 {0} 不能为空
```

## 业务异常的消息

`BizException` 携带的消息会先当作 key 查找，查不到按字面量原样返回：

```java
// 传字面量：原样返回（老代码不受影响）
throw new BizException(OrderErrorCode.ALREADY_CANCELLED, "订单已取消");

// 传 key：按当前语言解析
throw new BizException(OrderErrorCode.ALREADY_CANCELLED, "order.already-cancelled");
```

## 注意事项

- 字段级校验消息由 Bean Validation 产生，已经支持 `ValidationMessages.properties`，框架不重复翻译，
  只通过 `chaos.web.validation-field` 控制"字段名 + 校验消息"的拼接格式。
- 业务代码直接调用 `Result.failure(errorCode)` 时不经过解析器，拿到的是错误码的 `message()`。
  需要国际化请注入 `ErrorMessageResolver` 后使用 `Result.failure(errorCode, resolver.resolve(errorCode))`。
- 资源包各语言的 key 集合必须一致，缺 key 会静默回退成另一种语言；`ChaosMessageBundleTest` 在构建期拦截这类缺漏。
- 带 `{0}` 占位符的文案按 `MessageFormat` 处理，模式里的单引号需要写成两个。
